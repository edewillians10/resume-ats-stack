# 🏗️ Architecture (aka DevOps Therapy Diagram)

This stack consists of:

- **Reactive Resume** — UI for editing & generating resumes
- **Postgres** — persistent metadata + schema storage
- **Redis** — cache for auth sessions
- **MinIO (S3 compatible)** — stores profile photos + public assets
- **Browserless Chrome** — renders ATS-friendly PDF exports
- **Docker Compose** — container orchestration glue of the universe
- **Ansible** — because SSHing manually into servers is barbaric

No Kubernetes — because this is a résumé, not a bank.

# 🚀 Deployment Pipeline (Ansible-Driven)

This stack is deployed via **two Ansible playbooks in sequence**:

---

### **1. Preflight Playbook**

```sh
ansible-playbook preflight.yml -i inventory
```

Performs:

✔ system updates
✔ installs Docker + Docker Compose plugin
✔ configures runtime directories
✔ validates dependencies
✔ ensures nothing is on fire

---

### **2. Site Playbook**

```sh
ansible-playbook site.yml -i inventory
```

Deploys:

✔ full docker stack
✔ MinIO buckets
✔ bucket policies (public)
✔ Reactive Resume backend
✔ Browserless Chrome worker

After that, visit:

```
http://<host>:3000
```

and begin editing your resume for the 300th time like every other job seeker.

# 🗃️ MinIO Configuration

MinIO stores:

✔ profile pictures
✔ resume assets
✔ public static exports

Bucket required:

```
resumes
```

Policy must be set to:

```
public
```

Otherwise your face will not render and hiring managers may assume you're being artistic.

MinIO console:

```
http://<host>:9001
```

Default login:

```
minioadmin / minioadmin
```

Change in production (unless you want DevOps chaos speedrun mode).

# 💾 Persistence & Backup

This stack persists state via:

✔ Docker volumes
✔ MinIO buckets
✔ Postgres data

Backup:

```sh
docker compose down
tar zcvf resume-backup.tar.gz .
```

Restore:

```sh
tar zxvf resume-backup.tar.gz
docker compose up -d
```
